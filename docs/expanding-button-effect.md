# Expanding Button Effect

## Назначение

Этот документ фиксирует механику активной боковой кнопки из `History_map2`, чтобы потом использовать ее как переиспользуемый анимационный паттерн для разных элементов новой сайт-визитки.

Речь не про копирование старого компонента целиком, а про выделение его в понятную систему:

- что является ядром эффекта;
- какие слои визуала опциональны;
- как эффект должен вести себя при hover, click и idle;
- как абстрагировать это под разные компоненты страницы.

## Исходная реализация

Основные файлы старого проекта:

- `src/components/MainPage/ChapterActionButtons.jsx`
- `src/styles/components.scss`

Кнопка рендерится как абсолютный элемент поверх контейнера с плеером. Визуально это компактная капсула с иконкой, которая при наведении расширяется в сторону контента и раскрывает текст.

## Ядро эффекта

Эффект состоит из четырех обязательных частей.

### 1. Сжатое состояние

В покое кнопка выглядит как компактная капсула:

- фиксированная высота;
- малая стартовая ширина;
- внутри всегда видна иконка;
- текст либо скрыт, либо полностью нечитабелен.

В исходнике:

- `height: 60px`
- `width: 60px`
- `border-radius: 50px`

### 2. Направленное расширение

На hover кнопка не просто увеличивается, а именно "разжимается" в одну сторону:

- левая кнопка раскрывается вправо;
- правая кнопка раскрывается влево;
- иконка остается визуальной точкой опоры;
- текст проявляется уже внутри новой ширины.

Это главный смысл эффекта. Не glow, не tilt, не частицы, а именно контролируемое направленное расширение.

### 3. Появление метки

Текст кнопки должен появляться синхронно с расширением:

- opacity: от 0 к 1;
- небольшое смещение по оси X;
- при желании легкий blur на старте;
- текст не должен ломать геометрию кнопки рывком.

### 4. Усиление состояния

При hover кнопка должна ощущаться активной:

- чуть ярче;
- чуть крупнее;
- с более заметной глубиной;
- с усиленным контрастом фона или рамки.

Это важнее декоративных спецэффектов.

## Слои эффекта

Ниже разложение по уровням важности.

### Обязательный слой

Нужен почти в любой будущей версии:

- анимация ширины;
- анимация текста;
- аккуратный фон;
- бордер или контур;
- мягкая тень;
- логика направления.

### Желательный слой

Можно применять на ключевых элементах:

- курсорозависимый градиент внутри кнопки;
- легкий tilt по положению мыши;
- локальный glow вокруг элемента;
- небольшое усиление иконки.

### Опциональный слой

Использовать только там, где это действительно оправдано:

- частицы по клику;
- сложные циклические движения иконки;
- отдельный click-burst;
- многослойные свечения.

Для большинства секций портфолио этот уровень будет избыточным.

## Поведение по состояниям

### Idle

- кнопка компактная;
- иконка читается сразу;
- текст скрыт;
- фон спокоен;
- глубина умеренная.

### Hover

- ширина увеличивается;
- текст проявляется;
- контраст растет;
- иконка слегка оживает;
- если есть интерактивный градиент, он следует за курсором.

### Press

- кнопка чуть прожимается;
- может усиливаться локальный glow;
- click-feedback должен быть быстрым и коротким.

### Exit

- текст уходит первым или синхронно;
- ширина возвращается в базовую;
- все дополнительные слои плавно затухают;
- возврат должен быть пружинистым, но без резины.

## Анимационные принципы

Для новой реализации стоит сохранить следующие правила.

### Геометрия

- расширение делать через анимацию `width` или эквивалентную ей layout-анимацию;
- использовать пружину, а не линейный transition;
- не делать слишком большой overshoot.

### Ритм

- hover должен срабатывать быстро;
- раскрытие текста должно начинаться почти сразу;
- возврат может быть чуть спокойнее, чем раскрытие.

### Стабильность

- нельзя завязывать эффект на хрупкие absolute-хаки внутри текста;
- нельзя смешивать слишком много независимых transition, если они визуально спорят;
- базовая версия должна хорошо работать и без мышиного tilt.

## Семантическая модель для нового проекта

В новой сайт-визитке этот эффект надо мыслить не как "кнопка карты/документов", а как универсальный interactive pattern.

### Абстракция

Рекомендуемая сущность:

- `ExpandingEdgeButton`

Ее параметры:

- `side`: `left | right`
- `label`
- `icon`
- `tone`: например `amber | blue | neutral`
- `size`: `sm | md | lg`
- `interactiveLevel`: `minimal | enhanced | cinematic`

### Варианты применения

Тот же паттерн можно использовать для:

- кнопок рядом с hero-блоком;
- переключателей секций;
- project-preview controls;
- reveal-кнопок рядом с карточками кейсов;
- dock-элементов по краям экрана;
- CTA внутри fullscreen-блоков.

## Что переносим из старого проекта

- идею компактной капсулы;
- направленное расширение;
- синхронное проявление метки;
- разную геометрию для левой и правой стороны;
- пружинный характер анимации;
- цветовую персонализацию через `tone`.

## Что не переносим как есть

- перегруженный монолитный компонент;
- автосрабатывание логики контента при маунте;
- случайные частицы в каждом использовании;
- жесткую привязку к плееру;
- лишние декоративные анимации по умолчанию;
- неявные зависимости на шрифты, шумовые ассеты и старую SCSS-структуру.

## Рекомендуемая реализация в новой архитектуре

Эффект лучше собирать в три слоя.

### 1. Поведенческий слой

Отвечает за:

- hover-state;
- pointer tracking;
- pressed-state;
- направление раскрытия;
- variants для motion.

### 2. Презентационный слой

Отвечает за:

- размеры;
- фон;
- контур;
- текст;
- иконку;
- glow.

### 3. Токены

Отвечают за:

- цвета;
- радиусы;
- тени;
- длительности;
- stiffness/damping;
- уровни детализации эффекта.

Такой разрез позволит одним и тем же механизмом анимировать разные компоненты без копипасты.

## Минимальная версия для первого внедрения

Для первого production-варианта хватит:

- базовой капсулы;
- расширения по hover;
- появления текста;
- тонального фона;
- мягкого scale-feedback;
- аккуратной тени.

Tilt, glow-follow и particles стоит включать только после проверки, что базовая версия уже хорошо встроена в макет.

## Критерии качества

Эффект считается удачным, если:

- он читается за долю секунды;
- не выглядит как игрушечный UI-аттракцион;
- не ломает ритм страницы;
- одинаково хорошо работает на разных ширинах;
- без проблем деградирует на touch-устройствах;
- может использоваться на нескольких типах компонентов без переписывания логики.
